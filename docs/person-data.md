# A person's data

For whoever must know what HopIn holds about a person, how it exports that and what erasing the person removes and keeps.

HopIn holds a person's account (name and role) and their sessions in its own Postgres, which a restart keeps, and their seats in a call only in memory, which a restart forgets. A session's row holds the refresh token and the ID token in plain text and the session id only as its SHA-256. Members of the group `REALM_ADMIN_GROUP` names (or a group below it) download what HopIn holds about one person in their signed-in browser at `GET /api/admin/people/<keycloak id>/export`, and erase that person at `DELETE /api/admin/people/<keycloak id>` (below), each by the person's Keycloak id compared exactly. The export answers a ZIP holding `export.json`.

- **Listed:** the account's name and role, each session's start and end, and each seat's call link id and whether the person hosts that call. A seat that has not joined a call has no call link id.
- **Withheld, only counted:** session ids, refresh tokens, ID tokens and resume tokens (secrets), and the frames held for a resume in the person's own seats, which can carry other participants' names, the lines a joined agent reads (only while one is joined), the game master's lines, media state or connection descriptions.
- **Unknown id:** an id HopIn does not know answers an empty export (empty `data`, `files` and `withheld`) and creates nothing.
- **Not counted:** copies of the person's own frames in other participants' replay buffers (their name, media state, connection descriptions), which stay until newer frames push them out and which HopIn cannot trace to the person once the seat has ended, and a call the person hosts during its 60-second grace.
- **Logs:** the `account.changed` log lines carry the person's Keycloak id as `sub` until the host's log period ends. They are described here and not part of the export.

**The game master.** What a quiz run sends, to whom and on whose access is ruled in `docs/game-master.md`: the runs and their count (GM-05, GM-22), the starter's access and the single refresh grant (GM-08, GM-20), the API group (GM-19, GM-11), what the gateway receives and what never leaves the call (GM-21), the reveal request's answers (GM-43) and verdicts (GM-40), the counted score (GM-24), a spent budget (GM-13), the gateway call and its key (GM-42), what is never logged (GM-44), and the voice (GM-21, GM-32, GM-34, GM-36). HopIn logs no token in the voice path and not the voice's audio. HopIn keeps the quiz in memory until it ends. The gateway is the fleet's LiteLLM gateway (`litellm-front`). No token reaches a browser. The game's server side lives in `src/hopin/game/` and its agent connector in `src/hopin/agent/`, and `src/hopin/main.py` switches it in.

The shape of `export.json` follows the fleet's shared people contract (`docs/people.md` in the edge repository). HopIn admits only an admin's signed-in browser session, not an access token, so hal cannot call either route yet.

### Erasing a person

`DELETE /api/admin/people/<keycloak id>` erases the person in the same way the export is admitted: an admin's signed-in browser session, from HopIn's own page (the state-changing origin check applies). `?dry_run=true` changes nothing and answers what a real run would do. Both answer `200` with the people contract's body (`people_erasure` `1`, `app` `hopin`, `subject`, `dry_run`, `kinds` and `affects_others`; `docs/people.md` in the hal repository): `kinds` always lists `account` (0 or 1), `session` and `seat`, and `affects_others` lists the calls the person hosts that someone else takes part in, which end (`call`, `end`). Zero counts are listed. An unknown id, and a second run, answer zeros and create nothing. A database failure rolls the run back and answers `500` with a body that carries no counts; the run can be repeated. HopIn logs one `person.erased` line with the counts and never the id.

A real run deletes the person's sessions and then their account in one Postgres transaction, under the lock every sign-in, logout and token admission of every process takes, so those wait while it runs. Then this process closes the person's seats as a session end does and ends each call the person hosts at once for everyone, without the host's name. A dry run takes no lock, never waits and reads the same counts. Remove the person from the group `REALM_LOGIN_GROUP` names in Keycloak too, or they sign in again and get a new account.

Keycloak's back-channel logout (`/auth/backchannel-logout`, a route webauth serves, which the platform's realm points at HopIn) is not an erasure: it ends the person's sessions and keeps the account. A second logout for the same person, or one for a person HopIn does not know, changes nothing. A logout that fails midway answers 400 and ends nothing. Every back-channel logout does this, whatever started it, so an ordinary sign-out from Keycloak elsewhere also ends every session; the next sign-in uses the same account.

- **Removed at once:** every session of the person, refresh and ID tokens included, the account (name and role), the seats this process holds for the person (joined, not yet joined and parked) with their resume tokens and held frames, and each call the person hosts. A deleted row stays in Postgres's backups for up to three months.
- **Removed within 60 seconds:** seats on another process, which its next minute check closes once the session is gone; production runs one replica. A seat whose handshake read the session before the commit and opened after it stays until that check, and a second dry run counts it. A dry run counts only this process's seats.
- **Not counted and not erased:**
  - the person's frames in other participants' replay buffers (their name, media state, offers, answers and connection candidates, which carry network addresses), which stay until newer frames push them out (at most 256 per seat) or that participant's seat ends;
  - the person's name and answers in a running quiz, until it ends (the erasure does not look into the game; a quiz the person started ends for everyone, uncounted);
  - the agents library's listen records, which hold the person's principal and lapse within their 120-second lease, and for which the library offers no erase;
  - the registration of the person's own agent and the accounts of the person's own agents: an account stores no owner, so the erasure can neither find nor reach them; the registration lapses with its 120-second lease unless the agent's token keeps renewing it, and the agent cannot join a call without its owner's seat;
  - the lines of the joined agents' chat windows, which carry the speaker's name and text, and the person's transcribed sentences while an agent hears them, and which stay in the agent's own place until it ends;
  - the `account.changed` log lines (`kind` `user_created`, `role_changed` or `backchannel_logout`), which keep the person's Keycloak id until the host's log period ends.
  - the `request.ended` and `websocket.ended` log lines of the person's own earlier signed-in requests (`GET /api/account`, `/ws` and the like), which carry the person's Keycloak id as `sub` until the host's log period ends.

After a real run the export is empty. The person's own MCP token is refused (no account), and their cookie and websocket are refused by every process.
