# HopIn

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE) [![CI](https://github.com/overnightworks/hopin/actions/workflows/ci.yml/badge.svg)](https://github.com/overnightworks/hopin/actions/workflows/ci.yml)

HopIn is a self-hosted video call service. A signed-in member starts a call and shares its link, and friends join in the browser with nothing to install. The server signs people in and relays the setup messages between the members of a call; their chat lines go straight between the browsers. The camera video and the call's sound between the members flow directly between the browsers, or through the TURN relay when it is switched on and a direct path fails, still encrypted between the browsers. Three things do pass through the server: the game master's and agents' spoken sentences, which it has the speech service render and serves to each browser; while an agent hears a person, that person's microphone sound, which it forwards unread to the speech service; and, when an agent the person lets see looks, one still picture of their camera, held in memory only until the agent has it.

Only members of the Keycloak group `REALM_LOGIN_GROUP` names use it. Why HopIn exists and what it deliberately is not: [docs/VISION.md](docs/VISION.md). How it is built, how a call runs and what it trusts: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## What a Call Offers

- **Up to 6 people** in one call, each seeing and hearing everyone else
- **Screen sharing**, shown to the others as a large tile beside your camera
- **Microphone and camera** muted independently, with a preview before joining
- **Chat** beside the video: a line goes straight from browser to browser, up to 600 characters, and shows whether it arrived; HopIn's server sees it only while an AI is joined and reading along
- **Room lock**: the host locks the call from the "Mehr" menu, so no new person joins except the host's own account, which can return while there is room; the host unlocks at any time
- **Game master**: anyone in a call taps "Quiz starten" in the "Mehr" menu, and an AI asks everyone a quiz question in the chat, marked "KI", and on a card above it; everyone types an answer on the card, which nobody else sees, and can change it until the reveal; all see how many have answered. An answer has a length cap. The reveal comes when everyone has answered or the starter taps "Auflösen"; the game master names each answer and whether it was right, HopIn counts each person's right answers and the card shows the count, and the next question follows, five in all, then the game master's final score, which states the counted right answers. The starter or the host ends a quiz early with "Quiz beenden" in "Mehr", but not while the game master is thinking, and everyone then sees "Quiz beendet."; if the game master fails after the first question, the quiz ends, the starter sees why and the others see "Quiz beendet.". If the starter leaves the call, or is gone longer than 30 seconds, the quiz ends and everyone else sees "Quiz beendet: <name> ist gegangen."; if someone else leaves, the count shrinks and the reveal comes once everyone still there has answered. Someone who joins later plays from the next question. Every step runs on the starter's own AI access
- **Stage**: with `HOPIN_STAGE_APPS` naming an app, anyone in a call taps the app's entry in the "Mehr" menu (for Skat, "Skat zeigen") and pastes the link of a table of that app; every seat, and everyone who joins later, then sees the table on the stage in a frame of the app's own origin, and every video moves into a strip at the top. The frame runs scripts but may not use the camera, the microphone or screen capture, sends no referrer and cannot navigate the page. The person who brought the table or the host removes it with "Tisch entfernen", and anyone does once the person who brought it has left; the table is gone when the call ends. An app links to a table with `<HOPIN_PUBLIC_ORIGIN>/c/new?app=<name>&context=<key>`: the first visit starts a call showing the table, and a later one joins that call while it shows it. HopIn keeps only which table a call shows, in memory, and logs no table id; the app's game and its sign-in are the app's own
- **Reconnect**: a dropped connection keeps its place for a short while; the call waits for a dropped host before it ends
- **A SvelteKit page** that `make frontend` builds; the server serves that build

## Quick Start

You need Python 3.14+ and [uv](https://docs.astral.sh/uv/). Install with `make install`, set the required `HOPIN_` and `REALM_` settings and the three required `HOPIN_AGENT__` game settings from Configuration, and start the server with `make run`, which runs `hopin migrate` and then `hopin serve`; it listens on `HOPIN_HOST` and `HOPIN_PORT`.

`hopin verdict-repeatability [--runs N] [--minimum S]` asks the configured quiz master the same recorded reveals N times and reports how often its verdicts agree (GM-41 in `docs/game-master.md`); it reads only the `HOPIN_AGENT__` settings, costs real model calls, and the image carries it. `make verdict-repeatability RUNS=N` runs it from a checkout.

Sign-in returns the person to `HOPIN_PUBLIC_ORIGIN`, which must be https, so open HopIn at that origin (behind a TLS-terminating proxy), not at the plain listen address. Without the required settings, or with one malformed, HopIn refuses to start and prints one line per setting naming its environment variable, never its value. `HOPIN_REDIS_URL` names a Redis that every HopIn process shares for its request budgets and for the signals that wake an agent's open listen; a local `redis-server` is enough, and HopIn has no in-memory fallback. `HOPIN_DATABASE_URL` names a Postgres (a local one is enough) whose schema `hopin migrate` brings to the image's head; `hopin serve` refuses to start on a database that is not at that head, naming the command, and `/health` is not ready while the database does not answer. Run `hopin migrate` before every start of a new version: it reads only the two database settings, concurrent runs wait for one another, and a run at head changes nothing.

Sign-in needs a Keycloak client whose redirect URI is `HOPIN_PUBLIC_ORIGIN` + `/auth/callback` and that sends the groups claim, and an account in the group `REALM_LOGIN_GROUP` names.

Press "Anruf starten" and share the generated link.

## Run in a Container

HopIn runs on the platform (k3s with Flux) from its attested private image in GHCR; the platform's repository owns its manifests and the live settings. [Deployment View](docs/ARCHITECTURE.md#4-deployment-view) says what runs.

`compose.yaml` serves only the rollback path on hal. It owns the container's keys: the settings it sets, the four secret files it mounts read-only (the client secret, the session signing key and the two TURN key files), its two networks (HopIn's own, pinned, and the back-channel network on which only Keycloak reaches it as `hopin.hallucinai.de`), its restart policy and its healthcheck on `/health`. It publishes no host port and carries edge's routing label ([edge's README](https://github.com/overnightworks/edge#adding-a-tool-the-label-rule)); the `hal` commands are in [edge's README](https://github.com/overnightworks/edge#the-commands). Secret values never enter the environment.

A release is the `Release` workflow, which an agent dispatches with a version `YYYY.MM.DD.N` once review and CI are green. It gates `main`, builds and attests the image in GHCR and tags `vYYYY.MM.DD.N`. The image ref reaches production in a platform pull request the operator merges. On the rollback path, edge's catalog applies instead: `hal apply` takes the newest `v…` tag and publishes HopIn, and `hal stop hopin` stops it. Edge owns those commands.

## A Person's Data

HopIn holds a person's account (name and role) and their sessions in its own Postgres, which a restart keeps, and their seats in a call only in memory, which a restart forgets. A session's row holds the refresh token and the ID token in plain text and the session id only as its SHA-256. Members of the group `REALM_ADMIN_GROUP` names (or a group below it) download what HopIn holds about one person in their signed-in browser at `/api/admin/people/<keycloak id>/export`, by the person's Keycloak id compared exactly. The answer is a ZIP holding `export.json`.

- **Listed:** the account's name and role, each session's start and end, and each seat's call link id and whether the person hosts that call. A seat that has not joined a call has no call link id.
- **Withheld, only counted:** session ids, refresh tokens, ID tokens and resume tokens (secrets), and the frames held for a resume in the person's own seats, which can carry other participants' names, the lines a joined agent reads (only while one is joined), the game master's lines, media state or connection descriptions.
- **Unknown id:** an id HopIn does not know answers an empty export (empty `data`, `files` and `withheld`) and creates nothing.
- **Not counted:** copies of the person's own frames in other participants' replay buffers (their name, media state, connection descriptions), which stay until newer frames push them out and which HopIn cannot trace to the person once the seat has ended, and a call the person hosts during its 60-second grace.
- **Logs:** the `account.changed` log lines carry the person's Keycloak id as `sub` until the host's log period ends. They are described here and not part of the export.

**The game master.** "Quiz starten" is one run and each reveal, tapped or automatic, two (the answer, then the next question or the final score), five questions and eleven runs in all, each one chat completion at the fleet's LiteLLM gateway (`litellm-front`) with HopIn's own key, made for the starter: HopIn spends the session's refresh token once to read the starter's current groups from Keycloak, keeps the rotated one in the session, and starts the run only for a member of the API group (`HOPIN_AGENT__API_GROUP`); anyone else is told they have no access. The gateway receives the quiz prompt, this quiz's turns so far (its requests and the game master's lines), the request for the question, its answer or the final score, and the starter's fingerprint, a hash of their issuer and account id that keeps their budget apart. Each reveal request carries every answer given to that question, numbered and each with the player's name as the call shows it, and asks the game master for one verdict per answer through its `record_verdicts` tool; HopIn counts the right verdicts itself, and every later run of that quiz carries the answers again. A player without an answer is not listed. The final-score request carries each player's name with their counted right answers, which the game master states and never counts. A run sends no chat line and no media. A person over budget reads as unavailable, the same as an outage. Every line reaches everyone in the call; HopIn keeps the quiz in memory until it ends, and never logs a prompt, a line or what the gateway answered. With `HOPIN_SPEECH__ORIGIN` set, each line is also spoken: per line HopIn sends the line's text (with players' names in a reveal and the final score) to the operator's speech service with the starter's access token, which costs one more refresh grant, and HopIn's own workload token, and serves the returned WAV unchanged to the seats that got the line; no token reaches a browser, and HopIn never logs the text, a token or the audio, only an outcome code. A line whose voice fails stays text. The game's server side lives in `src/hopin/game/` and its agent connector in `src/hopin/agent/`, and `src/hopin/main.py` switches it in.

The shape of `export.json` follows the fleet's shared people contract (`docs/people.md` in the edge repository). HopIn admits only an admin's signed-in browser session, not an access token, so hal cannot call the route yet.

### Erasing a person

Remove the person from the group `REALM_LOGIN_GROUP` names in Keycloak and sign them out there. Keycloak's back-channel logout (`/auth/backchannel-logout`, a route webauth serves, which the platform's realm points at HopIn) ends the person's sessions in HopIn; the account stays. HopIn's own route that deletes an account is [#1093](https://github.com/overnightworks/hopin/issues/1093). A second logout for the same person, or one for a person HopIn does not know, changes nothing. A logout that fails midway answers 400 and ends nothing. Every back-channel logout does this, whatever started it, so an ordinary sign-out from Keycloak elsewhere also ends every session; the next sign-in uses the same account.

- **Removed at once, once the logout arrives:** every session of the person, refresh and ID tokens included. A deleted row stays in Postgres's backups for up to three months.
- **Removed within 60 seconds:** the person's own seats in calls, with the resume token and the frames held for it. A seat closes at the person's next frame or at the next minute check, or, for a seat whose connection dropped, when its 30-second wait ends. A call the person hosts ends for everyone after a further 60-second wait.
- **Stays until it ends by itself:** the person's answers and name in a running quiz, until the quiz ends; frames that already reached other participants (the person's name, media state, and offers, answers and connection candidates, which carry network addresses) stay in those participants' replay buffers, at most 256 frames per seat, until newer frames push them out or that participant's seat ends. The account (name and role) stays in Postgres, and a call the person hosts keeps them as its host until it ends. The `account.changed` log lines (`kind` `user_created`, `role_changed` or `backchannel_logout`) keep the person's Keycloak id until the host's log period ends.

Once the logout has arrived, the export shows the account and no sessions, and no seats once the calls have closed.

## A person's own agent

A person's own agent (first the operator's Claude Code) dials into a call the person sits in, through HopIn's MCP endpoint `POST /mcp` (the tools `join_call`, `leave_call`, `say`, `look` and, for an agent with an account of its own only, `accept_invitation` and `decline_invitation`; `src/hopin/agent/mcp.py` and `src/hopin/participation/`). Everyone in the call then sees a tile with the name the person gave the agent, a "KI" badge and the person's name; the person or the host removes it. The agent joins only a call in which its person holds exactly one live seat, and it leaves when that seat leaves for good or when it calls `leave_call` with the call's id. It has no host or admin right. With the switch „Agent darf mich sehen“ on its tile, which starts off for every agent and which only the person turns on, it takes one still picture of the person's own camera with `look` (the tool `look`; at most 1280 px, one JPEG, kept only until it is handed over, never stored or logged, at most 6 looks a minute); the agent's tile shows a mark at each look (`docs/call.md`, CALL-62 and CALL-63). It writes a line in the chat with `say` and reads the chat from its join on through the resource of its call's window (below).

The bearer is accepted on this one path and nowhere else. webauth's gate admits a token whose audience is `HOPIN_PUBLIC_ORIGIN` + `/mcp` alone or exactly that and HopIn's own client id (any other extra audience is refused), the client `REALM_MCP_CLIENT_ID` names, the scope `REALM_MCP_SCOPE` names and membership of the Keycloak group `REALM_MCP_GROUP` names, for a person who has signed in once; the metadata of RFC 9728 is public at `/.well-known/oauth-protected-resource/mcp`. An agent's own account (the group `REALM_AGENT_GROUP` names, any client of the realm, created on its first admission) is admitted as `user` too. `join_call` serves only a person's own agent (an own account gets `invitation_only`), an own account reads the resource `member://standing` (`resources/read`; it wakes on a change through `subscriptions/listen`; the endpoint serves revision 2026-07-28 only; a person's own agent has no standing, and its read is an unknown resource): its whole standing, each place it is invited to, active in or paused in, and nothing for one it was removed from, and `accept_invitation(place, invitation, epoch)` (the runtime's shared arguments, the place's kind `call`) serves only an own account (a person's own agent gets `own_account_only`) and answers `{room, name}`, `leave_call(room)` serves both and acts only on a joined place, and `say(room, text)` serves both, answers `{}` and acts only on a joined place: every seat reads the line under the agent's name with the AI mark, 1 to 600 characters with no control character, else `bad_line` or (no joined place there, an invited agent included) `gone`, for the agent alone; no log line carries the text, and `speak(place, text)` serves both, answers `{duration_ms}` and tells every seat the sentence's voice in order (CALL-60 in `docs/call.md`), or `{written: true}` when the voice fails and the sentence stands in the chat as the agent's line instead (CALL-61), with `not_active`, `too_long` and `unavailable` for the agent alone. Every agent joined in a call, of either kind, reads the call's chat from its join on at the resource that is `place_window_uri` of the place `call/<room>` (listed by `resources/list` for each call where the principal holds a joined agent, next to `member://standing` for an agent with an account of its own, and woken by `subscriptions/listen` when a line is added): a window of the newest 100 lines and at most 256 KiB of their text with the agent's own lines marked `own` and its `voice_state` (`unavailable` after a sentence's voice failed, `available` again at the next sentence the speech service voiced; CALL-61), kept in memory only and gone with the agent's place (leave, removal, the sponsor's seat leaving for good, a lease's end, the call's end, shutdown). A person's own agent reads the places of its own person, never those of an agent it sponsors; any other room, an invited agent's room and a room left or ended is an unknown resource. The game's lines are not in the window. A member of the group `HOPIN_AGENT_ADDERS` names for the agent's owner adds the agent from their seat's "Mehr" while the owner holds exactly one seat in the same call; the call's host and each such member see the "Mehr" control even with no agent listed, which then says one sentence; the agent shows under the name its token carries, never its account's username, and leaves when its sponsor or the host removes it, when its owner's seat leaves for good, or when it has made no call for 120 seconds. The disclosure gate binds it as well, because it needs that MCP group too. The cookie session and its CSRF protection govern every other route, and the bearer opens neither `/api` nor `/ws`. Until the privacy text names the person's own AI agent and its provider as a recipient at the person's wish, nobody but the operator is put into that group; it is the disclosure gate, and the operator alone controls it. Bounds: agents take places of the call like people (`HOPIN_MAX_PARTICIPANTS_PER_ROOM`, CALL-47), so a join answers `busy` only when the call has no place free.

## Configuration

`src/hopin/config/settings.py` owns the settings; every one is an environment variable with the `HOPIN_` prefix, except the seven `REALM_` keys, which name HopIn's objects in the Keycloak realm under the same keys in every app. The client secret, the session signing key and the two TURN key files are the exception in content: the variables name files, HopIn reads them at start, and the secrets never enter the environment.

| Variable | Default | Description |
|---|---|---|
| `HOPIN_HOST` | `0.0.0.0` | Server bind address |
| `HOPIN_PORT` | `8080` | Server port |
| `LOG_LEVEL` | `info` | The root log level (`debug`, `info`, `warning`, `error`, `critical`); logline reads it without the `HOPIN_` prefix, and anything else stops the start |
| `SERVICE_VERSION` | unset; the release image sets it to the release version | The `version` of every log line, which logline reads without the `HOPIN_` prefix |
| `HOPIN_STUN_SERVER` | `stun:stun.cloudflare.com:3478` | STUN server for NAT traversal, served to the browser at `/api/ice-servers` |
| `HOPIN_TURN_PROVIDER` | `off` | `off` or `cloudflare`. With `cloudflare`, each call start asks the provider for a TURN credential that lives 12 hours and serves it with the STUN entry. Switching off (it takes a restart) stops new TURN credentials only: credentials already handed out stay valid at the provider until their 12 h end |
| `HOPIN_TURN_KEY_ID_FILE` | unset | Absolute path of the file holding the TURN key's ID; required when TURN is on |
| `HOPIN_TURN_API_TOKEN_FILE` | unset | Absolute path of the file holding the TURN key's API token; required when TURN is on |
| `HOPIN_MAX_PARTICIPANTS_PER_ROOM` | `6` | Maximum places per call, from `2` to `6`; people and joined agents take them alike |
| `HOPIN_OIDC_ISSUER` | required | The Keycloak realm URL, https, without a trailing slash |
| `HOPIN_OIDC_CLIENT_SECRET_FILE` | required | Absolute path of the file holding the secret of the client `REALM_CLIENT_ID` names |
| `HOPIN_PUBLIC_ORIGIN` | required | HopIn's own https origin, without a path or trailing slash |
| `HOPIN_SESSION_SECRET_FILE` | required | Absolute path of the file holding the session signing key, at least 32 characters |
| `HOPIN_TRUSTED_PROXIES` | empty | Comma-separated addresses and CIDR blocks of the proxies whose `X-Forwarded-For` names the person's address for the rate limits and the request log; empty trusts none, so every request counts against its direct peer |
| `REALM_CLIENT_ID` | required | The Keycloak client HopIn signs in as |
| `REALM_LOGIN_GROUP` | required | The Keycloak group path whose members sign in, such as `/apps/hopin`, compared exactly; a group below it admits too |
| `REALM_ADMIN_GROUP` | required | The Keycloak group path whose members administer, a group below it included; it lies below `REALM_LOGIN_GROUP` |
| `REALM_MCP_GROUP` | required | The Keycloak group path whose members' agents may reach `/mcp`, compared exactly |
| `REALM_MCP_SCOPE` | required | The Keycloak scope a token for `/mcp` carries |
| `REALM_AGENT_GROUP` | required | The Keycloak group path of agents' own accounts, which `/mcp` admits from any client |
| `REALM_MCP_CLIENT_ID` | required | The public Keycloak client a person's own agent signs in through |
| `HOPIN_REDIS_URL` | required | The `redis://` or `rediss://` URL of the Redis that every HopIn process shares. The per-address request budgets live there, so a budget spent through one process is refused through the others, and so do the signals that wake an agent's open listen. HopIn refuses to start without it and has no in-memory fallback; with Redis down `/health` is not ready and every budgeted route answers 503 |
| `HOPIN_DATABASE_URL` | required | The `postgresql://user@host:port/database` URL of the Postgres that every HopIn process shares; no password and no query parameter, which HopIn refuses. `hopin migrate` and `hopin serve` read it; the schema holds the accounts and the sessions, which every process reads and writes; an empty port (`host:/database`) is refused. With the database down `/health` is not ready |
| `HOPIN_DATABASE_PASSWORD_FILE` | required | Absolute path of the file holding only the database user's password |
| `HOPIN_AGENT__GATEWAY__ORIGIN` | required while the game is installed | The gateway's http(s) origin (scheme, host and optional port), `http://litellm-front:4000` in `compose.yaml` |
| `HOPIN_AGENT__GATEWAY__KEY_FILE` | required while the game is installed | Absolute path of the file holding HopIn's gateway key, read at every turn, so a missing or unusable file does not stop the start: the turn then reads as unavailable |
| `HOPIN_AGENT__GATEWAY__CA_FILE` | required for an HTTPS origin, refused for an HTTP one | Absolute path of the CA the gateway's HTTPS certificate is trusted by |
| `HOPIN_AGENT__API_GROUP` | required while the game is installed | The full Keycloak group path that admits a person to the game master, compared exactly, so a subgroup does not admit |
| `HOPIN_STAGE_APPS` | `[]` | The apps whose tables a call shows on its stage in a frame: a JSON list of `{"name", "title", "origin", "frame_path"}`. `name` is lowercase letters, digits and hyphens, a letter first, 32 characters at most, and stays stable, because it feeds the label of the app's person keys (`hallucinai/<name>/person-key/v1`) and renaming it empties every chair. `title` is what the page calls the app. `origin` is the app's https origin (scheme, lowercase ASCII host, optional port other than 443, no path); the page may frame exactly the listed origins. `frame_path` starts with `/`, holds `{context}` once and has no query, fragment or dot segment; a table's frame loads `origin` + `frame_path` with the table's key in place of `{context}` + `?mode=call`. Names and origins are unique, and no origin is `HOPIN_PUBLIC_ORIGIN`, else the start is refused; so does a malformed value, without echoing it. Empty means no stage. |
| `HOPIN_AGENT_ADDERS` | `{}` | A JSON object that maps an owner's Keycloak subject to the full group path whose members may add that owner's agent with an account of its own, compared exactly; unset or `{}` means nobody adds, and a malformed value stops the start without echoing it |
| `HOPIN_FIGURE_SOURCES` | `[]` | A JSON list of URL prefixes an agent with an account of its own may bring its figure from (each https, a lowercase host with no port or user, no query or fragment, and a path that starts and ends with `/` and holds only ASCII letters, digits and `-._~/`, with no empty, `.` or `..` segment); unset or `[]` means no figure is fetched and every agent shows its symbol. HopIn fetches a figure, each clip of a persona's gestures and a persona's room only from such a prefix, follows at most one redirect, only to https, and serves only bytes whose sha256 matches. An allowed prefix trusts its host's redirects for a figure, a clip and a room: an open redirect on an allowed host lets an agent make HopIn send one GET without credentials to another https address, whose answer it never sees. A malformed value stops the start, naming only the setting |
| `HOPIN_SPEECH__ORIGIN` | unset | The speech service's http origin (scheme, host and optional port, no path); unset means the game master stays silent |
| `HOPIN_SPEECH__VOICE` | `de_DE-thorsten-medium` | The speech service's catalogue voice the game master's lines are spoken with, and the one voice for an agent's sentences whose accept names no voice (an accept's voices, first choice first, take precedence: each sentence is spoken with the first of them the speech service's health offers ready, and written as a line when none is, and while an agent's voice is unavailable HopIn reads the health every 5 seconds to turn it available again); it must speak German, the page's default language, so a value outside the catalogue or a voice without German stops the start |
| `HOPIN_SPEECH__AUDIENCE_SCOPE` | required when the origin is set | The one Keycloak scope whose token the speech service admits (`speech-service-audience`); sign-in asks for it only with the voice on |
| `HOPIN_SPEECH__HEARING` | `false` | Whether an agent hears its sponsor, who sends their microphone sound through HopIn to the speech service; on needs the origin and the audience scope, or the start stops |
| `HOPIN_SPEECH__SPEAKING` | `false` | Whether an agent with an account of its own speaks in a call: HopIn renders its sentences through the speech service under the agent's own account and plays them to every seat; on needs the origin and the audience scope, or the start stops |

The `HOPIN_AGENT__` settings are read by the connector's `AgentSettings`, the `HOPIN_SPEECH__` ones by its `SpeechSettings` (which stays when the game is removed), and `HOPIN_AGENT_ADDERS` and `HOPIN_FIGURE_SOURCES` by participation's `ParticipationSettings`; a missing or malformed one stops the start and echoes no input.

Agents dial in through `POST /mcp` with a bearer token and need no setting, except that an agent with an account of its own is added only where `HOPIN_AGENT_ADDERS` maps its owner: the endpoint's audience is `HOPIN_PUBLIC_ORIGIN` + `/mcp`, and the realm decides who may use it (see "A person's own agent"). HopIn refuses to start without the required `HOPIN_` settings, any of the seven `REALM_` keys (a group key that is no group path included), or the required `HOPIN_AGENT__` settings, without the page build (`make frontend` writes it), when a secret file cannot be read, or when TURN is on and a key file is missing, empty or malformed, and says which setting is at fault, never what a file holds.
